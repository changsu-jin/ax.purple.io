## 풀고 있는 문제

AI 코딩 에이전트의 도입은 빠르게 확산되고 있지만, 조직 차원의 통제는 따라가지 못합니다. Claude Code, Cursor, Copilot 등 에이전트마다 설정 방식이 다르고, 개발자마다 사용법이 제각각이면 코딩 컨벤션이 무너지고 리뷰 기준이 흐려집니다.

문제의 핵심은 "**에이전트가 조직의 규칙을 모른다**"는 것입니다. 사람은 온보딩을 통해 규칙을 익히지만, 에이전트에게는 그런 과정이 없습니다.

## 접근 방식

"**규칙을 코드로, 에이전트에 주입한다**"

우리는 사내 규칙을 에이전트가 이해할 수 있는 형태로 변환하는 접근을 택했습니다. Vercel이 제안한 Agent Skills 스펙을 활용하면, 에이전트 종류에 관계없이 동일한 규칙을 적용할 수 있습니다.

### 스킬의 구조

하나의 스킬은 하나의 규칙 묶음입니다. 코드 리뷰 기준, 보안 체크리스트, 테스트 작성 규칙 등을 각각 독립적인 스킬로 만들고, 역할별 태그로 분류합니다.

```
frontend, backend  →  해당 역할에 필요한 스킬만 설치
security, review   →  보안팀, 리뷰어용 스킬
onboarding         →  신규 입사자용 기본 스킬셋
```

### 배포 방식

원커맨드 설치 스크립트로 온보딩을 간소화했습니다. 개발자가 팀에 합류하면 태그 하나로 필요한 스킬 전체가 설치됩니다. 스킬이 업데이트되면 전사에 일괄 반영되므로, 규칙 변경 시 개별 통보 없이 에이전트가 자동으로 최신 규칙을 따릅니다.

### 스킬 카탈로그

전체 스킬 현황을 한눈에 볼 수 있는 카탈로그 사이트를 운영합니다. 어떤 스킬이 있는지, 각 스킬이 어떤 규칙을 담고 있는지, 어떤 태그에 연결되어 있는지 확인할 수 있습니다.

## 배운 것

- **에이전트 거버넌스는 코드로 해야 한다.** 문서로 된 가이드라인은 사람에게는 통하지만, 에이전트에게는 통하지 않습니다.
- **스킬의 단위는 작을수록 좋다.** 하나의 스킬이 너무 많은 규칙을 담으면 관리가 어려워집니다. 단일 책임 원칙이 스킬에도 적용됩니다.
- **태그 기반 배포가 역할 기반 배포보다 유연하다.** 역할은 바뀔 수 있지만, 태그 조합은 어떤 상황에도 대응합니다.
- **skill-creator로 스킬 생성 자체를 자동화할 수 있다.** 기존 문서나 위키에서 규칙을 추출하여 스킬을 자동 생성하는 워크플로우를 만들면, 스킬 수가 빠르게 늘어납니다.
