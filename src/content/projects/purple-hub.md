## 풀고 있는 문제

시스템을 개선하거나 자동화하려면 비즈니스 맥락에 대한 깊은 이해가 필요합니다. 그런데 이 지식은 대부분 **사람의 머릿속**에 있습니다. 담당자의 경험, 흩어진 문서, 레거시 코드 안에 분산되어 있어서, 새로운 사람이 오면 처음부터 다시 배워야 합니다.

AI 에이전트도 마찬가지입니다. 코드를 읽을 수는 있지만, "왜 이렇게 만들었는지", "이 데이터가 어떤 비즈니스 의미를 가지는지"는 알 수 없습니다. AI가 실질적인 도움을 주려면 이 맥락에 체계적으로 접근할 수 있어야 합니다.

## 접근 방식

"**사람이 아는 것을 AI가 이해할 수 있는 형태로 바꾼다**"

### 지식의 4계층 구조화

도메인 지식을 4개 레이어로 나누어 체계적으로 수집합니다.

| 레이어 | 내용 | 예시 |
|--------|------|------|
| 시스템 맵 | 전체 아키텍처 개요 | 서비스 간 의존관계, 데이터 흐름 |
| 도메인 모델 | 핵심 엔티티와 비즈니스 규칙 | 주문 상태 전이, 정산 규칙 |
| API/플로우 | 주요 흐름과 시퀀스 | 결제 프로세스, 배송 상태 변경 |
| 운영 컨텍스트 | 설정, 연동, 배포 정보 | 외부 연동 API, 배치 스케줄 |

### 3채널 접근

지식 허브를 활용하는 사람의 역할에 따라 세 가지 채널을 제공합니다.

1. **개발자**: 코드 에디터에서 직접 지식 허브에 접근하여 코드와 맥락을 함께 봅니다
2. **비개발자**: 대화형 AI 앱을 통해 자연어로 도메인 지식을 질문합니다
3. **자동화**: CI/CD 파이프라인에서 코드 변경 시 메타데이터를 자동 갱신합니다

### 지식의 품질 관리

문서를 만드는 것보다 **유지하는 것**이 어렵습니다. 우리는 지식의 품질을 4단계로 측정합니다.

- **Seed** — 작성됨 (존재만 확인)
- **Active** — 5회 이상 참조됨 (실제 활용)
- **Proven** — 70% 이상의 문제 해결에 기여 (효과 검증)
- **Gold** — 90% 이상의 해결률, 30회 이상 참조 (핵심 자산)

이 등급 체계를 통해 어떤 지식이 실제로 도움이 되는지 데이터로 판단하고, 기여자에게는 포인트 보상을 제공합니다.

## 기대 효과

- 신규 인력 온보딩 시간 단축 — 도메인 지식을 AI가 안내
- 반복적인 "이거 어떻게 되는 거예요?" 질문 감소
- AI 에이전트의 코드 이해도 향상 — 맥락 있는 코드 리뷰, 자동 문서화
- 담당자 부재 시에도 운영 지속 가능
